# 3色 링크데이 바이브코딩 체험실

초등교사가 Codex와 대화하며 정적 웹앱을 만들고 함께 나누는 작품 전시관입니다. 처음에는 작품이 없는 상태로 시작합니다. 별도 패키지 설치·로그인·API·데이터베이스 없이 GitHub Pages에서 실행됩니다.

## 구성

```text
index.html                    작품 전시관: 목록 로딩·검색·카드·빈 상태·오류 안내
gallery.json                  공개 승인된 작품 목록 (초기값 [])
AGENTS.md                     참가자 응대와 운영·안전 규칙
works/                        참가자별 독립 폴더 (처음에는 .gitkeep만 존재)
  001/index.html              첫 작품이 생길 때 생성
  002/index.html              다음 작품이 생길 때 생성
scripts/validate_gallery.py   작품 목록과 실행 파일 검사
.github/workflows/validate.yml PR/main 변경 시 구조 검사
.nojekyll                     GitHub Pages에서 정적 파일을 그대로 제공
```

## 운영자가 처음 할 일

1. GitHub에서 이 저장소의 `main` 파일을 확인합니다.
2. **Settings → Pages → Build and deployment**에서 Source를 **Deploy from a branch**, Branch를 **main**, 폴더를 **/ (root)**로 선택하고 저장합니다.
3. Actions의 Pages 배포가 완료된 뒤 Pages 설정에 표시된 실제 주소를 엽니다. 별도 사용자 도메인이 없다면 예상 주소는 `https://kalapui36.github.io/linkday/`입니다. 설정만으로 즉시 배포되지는 않습니다.
4. 빈 전시관 안내가 나타나는지 확인합니다. 이후 `main`에 반영하면 자동으로 재배포됩니다. `Validate gallery`는 구조 검사이며 Pages 배포 작업과 별개입니다.
5. Cloud 환경 설정에 저장된 시작 지침을 검토·저장하고 환경을 게시해 향후 작업에서 재사용합니다. 환경 게시와 GitHub Pages 배포는 서로 다른 절차입니다.

Pages 설정에는 저장소 관리 권한이 필요합니다. 저장소가 비공개이면 계정 플랜에서 Pages를 지원하는지 확인하세요. Pages 공개 범위도 확인하고, 전시 내용은 인터넷 공개를 전제로 검토하세요. 저장소의 공개 범위를 임의로 바꾸지 않습니다.

## 참가자마다 새 Codex Cloud 작업 시작

1. 직전 참가자의 반영이 끝났는지 확인하고 최신 `main`을 준비합니다. 완성하지 않은 작품은 별도 브랜치로 보관합니다.
2. **새 Codex Cloud 작업**을 시작하고 저장소 `kalapui36/linkday`, 기준 브랜치 `main`, 이 저장소용 환경을 선택합니다. 화면의 메뉴 명칭은 제품 버전에 따라 다를 수 있습니다.
3. 운영자가 중복되지 않는 작품 번호를 배정합니다. 동시에 진행할 때는 번호 배정표를 운영자가 별도로 관리하세요. 참가자 학교명이나 실명은 이 표를 위해 저장소에 넣지 않습니다.
4. 운영자가 다음 시작 문구를 입력합니다. `001`은 실제 배정 번호로 바꿉니다.

   > 새 참가자 체험을 시작해 주세요. AGENTS.md를 따르세요. 이번 작품 번호는 001입니다. 운영자로서 works/001/ 안의 새 작품 파일 제작과 수정을 승인합니다. 참가자가 ‘코딩 시작’이라고 말하기 전에는 파일을 작성하지 마세요. 목록 등록과 GitHub 반영·배포는 작품 완성 후 별도로 검토하겠습니다.

5. 참가자는 인사 → 공개 표시 정보 확인 → 아이디어 대화 → 기능·디자인 정리 → **코딩 시작** → 제작·수정 → **작품 완성** 순서로 체험합니다.
6. 다음 참가자는 반드시 **새 작업·새 대화**로 시작합니다. 기존 대화에 새 참가자를 이어 붙이지 않습니다. 각 작업의 기존 체크아웃을 사용하며 별도 Git worktree를 만들 필요는 없습니다.

참가자가 자기 프로그램을 실행하는 것 외에 이 전시 페이지에서 Codex 작업을 자동 생성하거나 GitHub에 직접 저장하는 기능은 없습니다. 체험 시작과 공개 반영은 운영자가 진행합니다.

## 작품 완성·검토·공개

1. Codex가 보여주는 작품 실행 결과, 실제 검증 내역, 변경 파일, 전시 카드 문구를 확인합니다. 학생 실명·연락처·성적·사진·인증 정보가 없는지 검토합니다.
2. 학교명과 표시 이름은 각각 공개 동의를 확인합니다. 별명을 쓸 수 있고 응답도 생략할 수 있습니다. 비공개 정보는 코드·JSON·커밋·PR에도 기록하지 않습니다.
3. 승인할 때 아래처럼 운영자의 의사를 명시합니다.

   > 운영자입니다. 작품 001의 실행 결과와 공개 정보를 확인했습니다. 검토한 작품과 전시 목록 추가안을 커밋·푸시하고 PR로 준비해 주세요. main 병합은 제가 진행하겠습니다.

4. Codex는 최신 `main`에서 번호 충돌을 확인하고 해당 작품 폴더와 `gallery.json` 추가 항목만 포함하는 브랜치·PR을 준비합니다. GitHub API 권한이 없으면 브랜치를 푸시한 뒤 GitHub에서 **Compare & pull request**로 PR을 만들 수 있습니다. 푸시 권한까지 없으면 권한 있는 운영자가 마무리해야 합니다.
5. PR에서 기존 작품이 보존되었는지, `Validate gallery` 검사가 통과했는지, 공개 정보와 기능이 적절한지 확인합니다. 저장소 설정에서 필요하면 검사를 병합 필수 조건으로 지정할 수 있습니다.
6. 운영자가 승인한 PR을 `main`에 병합합니다. 병합은 공개 배포를 유발하므로 최종 검토 후 진행합니다. 동시에 등록한 작품이 있으면 최신 목록의 항목을 모두 보존하고 새 번호를 배정합니다.
7. Pages 배포 완료 후 전시관 카드와 실제 작품을 다시 확인합니다. 사용 중인 페이지가 오래된 경우 새로고침합니다.

## 작품 목록 형식

아래는 설명용 예시입니다. 초기 `gallery.json`은 빈 배열입니다.

```json
[
  {
    "id": "001",
    "title": "우리 반 랜덤 발표 도우미",
    "description": "가상 번호로 발표 순서를 뽑는 도구입니다.",
    "creator": "초록쌤",
    "school": "공개에 동의한 학교명"
  }
]
```

- 필수 항목: `id`, `title`, `description`. 선택 항목: `creator`, `school`.
- 이름 비공개 시 `creator`를, 학교명 비공개 시 `school`을 생략합니다. 이름이 없으면 ‘익명의 선생님’으로 표시됩니다.
- 번호는 `001`부터 시작하는 3자리 이상 숫자입니다. 폴더명과 정확하게 일치해야 하며, 기존 번호나 폴더를 재사용하지 않습니다.
- 홈페이지는 경로를 `./works/{id}/`로 계산합니다. 임의의 URL, HTML, 이메일 등 다른 필드는 추가하지 않습니다. 카드 정보는 HTML로 해석하지 않고 텍스트로 표시합니다.
- 각 작품은 실행 가능한 `index.html`을 포함하고 전시관 복귀 링크 `../../`를 제공합니다. 루트 절대 경로 `/works/...`는 프로젝트 Pages에서 잘못된 경로이므로 쓰지 않습니다.
- 가능하면 CSS와 JavaScript를 해당 HTML에 포함합니다. 외부 전송이나 서버가 필요 없는 도구를 우선하고, 실제 학생 정보 대신 가상 자료를 사용합니다.

## 로컬 개발·검증

Python 3만 있으면 됩니다. 저장소 루트에서 실행합니다.

```sh
python3 scripts/validate_gallery.py
python3 -m http.server 8000 --bind 127.0.0.1
```

로컬 브라우저에서는 `http://127.0.0.1:8000/`으로 확인합니다. HTML을 더블 클릭하는 `file://` 방식은 JSON 로딩이 차단될 수 있습니다. Cloud 작업에서는 내부 HTTP 요청과 사용 가능한 브라우저 도구로 검증하며, localhost 주소는 외부 참가자용 링크가 아닙니다.

확인할 내용:

- 초기에는 작품이 0개이며 빈 전시관 안내가 보이는가?
- 등록 후 카드의 제목·설명·공개 표시 정보가 맞고 클릭하면 해당 작품이 열리는가?
- 검색, 검색 결과 없음, 목록 로딩 실패 시 안내와 재시도가 작동하는가?
- 작품의 핵심 기능, 모바일 화면, 키보드 조작, 전시관 복귀가 작동하는가?
- diff에 기존 작품 삭제·덮어쓰기·다른 참가자의 변경·비공개 정보가 없는가?

구조 검사 도구는 앱 기능, 동의 여부, 개인정보 포함 여부를 자동 판단하지 않습니다. 자동 검사와 운영자의 내용 검토를 함께 진행해야 합니다.

## 문제 해결

- **목록 로딩 실패:** HTTP로 열었는지, `gallery.json`이 존재하는지, JSON 문법과 필드 형식이 맞는지 확인합니다.
- **작품 404:** 목록의 번호와 실제 폴더명, `index.html`의 대소문자, Pages 배포 완료 여부를 확인합니다.
- **Pages 주소가 열리지 않음:** Pages의 `main`/루트 설정, Actions 배포 로그, 저장소 권한·플랜을 확인합니다.
- **번호 충돌:** 기존 작품을 보존한 채 새 작품을 미사용 번호로 옮기고 목록을 함께 수정합니다. 기존 폴더를 덮어쓰지 않습니다.
- **비공개 정보 공개:** 운영자에게 즉시 알리고 노출 범위를 확인합니다. 인증 정보라면 폐기·재발급하고 별도의 이력 정리 절차를 협의합니다. 현재 파일 삭제만으로 Git 기록에서 사라지지는 않습니다.
